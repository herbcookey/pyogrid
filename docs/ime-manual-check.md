# 한글 입력 손 확인

자동 테스트는 한글 조합을 Chromium에서만 흉내 낼 수 있고, 그것도 실제 입력기와 이벤트 순서가 다르다 (CDP는 조합을 끝내는 Enter를 보통 키로 보낸다).
그래서 조합 중에 누른 Enter·Tab·방향키는 실제 기기에서 손으로 확인한다.

## 준비

- 페이지: [demo/input-log.html](../demo/input-log.html) (배포 사이트: https://herbcookey.github.io/pyogrid/demo/input-log.html?lang=ko).
  그리드 입력칸의 keydown, compositionstart, compositionend, input을 순서대로 찍고, 각 이벤트 뒤의 그리드 상태(편집 중인지, 활성 칸)를 보여 준다.
- 입력기: macOS는 "한국어 - 2벌식", Windows는 "Microsoft 입력기 (한국어)".
- 한 항목을 확인할 때마다 **지우기**를 누르고 시작한다. 확인이 끝나면 **기록 복사**로 기록을 남긴다 (첫 줄에 브라우저 정보가 들어간다).

## 확인할 환경

| 환경 | 브라우저 |
|---|---|
| macOS (실기기) | Safari, Chrome, Firefox |
| Windows | Chrome, Edge, Firefox |

## 확인 항목

"글자" 컬럼의 첫 셀(0,0)을 누르고 시작한다. 모든 항목에서 마지막 글자가 아직 조합 중일 때(밑줄이 있을 때) 키를 누른다.

| # | 할 일 | 맞는 결과 |
|---|---|---|
| 1 | "한글"을 치고 Enter | 셀에 "한글"이 저장되고 활성 칸이 한 칸 아래(1,0)로. 그 칸은 편집 중이 아니다. 기록에 Enter keydown이 두 번 보이면 두 번째는 prevented가 true이고 상태가 바뀌지 않는다 |
| 2 | "한글"을 치고 Tab | "한글"이 저장되고 오른쪽 칸(0,1)으로 한 칸만. 두 칸 가거나 포커스가 그리드 밖으로 나가면 안 된다 |
| 3 | "한글"을 치고 ↓ | "한글"이 저장되고 한 칸 아래로 한 칸만 |
| 4 | "한글"을 치고 ↑ (1,0에서 시작) | "한글"이 저장되고 한 칸 위로 한 칸만 |
| 5 | "한글"을 치고 ← 또는 → | 저장하지 않고 편집을 계속한다. 커서만 글자 안에서 움직인다 (조합은 확정된다) |
| 6 | "한글"을 치고 Shift+Enter | "한글"이 저장되고 한 칸 위로 |
| 7 | 셀을 고르고 바로 "가"를 친다 | 첫 글자부터 "가"가 들어간다 (ㄱ이 빠지거나 두 번 들어가지 않는다). 후보 창·조합 글자가 셀 옆에 보인다 |
| 8 | "목록" 컬럼에서 "바"를 친다 | 목록이 열리고 "바나나"가 고른 줄이 된다. Enter로 저장 |
| 9 | 1번을 빠르게 다섯 번 이어서 (각 칸에 "가", Enter) | 다섯 칸에 하나씩 저장되고 다섯 칸 아래로. 건너뛰는 칸이 없다 |

## 기록에서 볼 것

- 조합을 끝낸 키가 어떻게 오는지: `isComposing: true`이거나 `keyCode: 229`인 keydown이 compositionend **앞**에 오는가, 같은 키의 보통 keydown이 compositionend **뒤**에 한 번 더 오는가.
- 한 번 더 오면 compositionend와의 timeStamp 차이(Δms). 그리드는 80ms 안의 같은 키를 버린다. 차이가 80ms에 가깝거나 넘으면 기록을 이슈에 붙인다.
- Safari에서는 그 keydown의 timeStamp가 compositionend보다 이를 수 있다 (Δms가 음수). 그래도 버려져야 한다.
