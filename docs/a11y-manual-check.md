# 스크린 리더 손 확인

자동 검사(test/e2e/a11y.spec.js)는 axe 규칙과 ARIA 속성 값까지만 본다. 스크린 리더가 실제로 무엇을 읽는지는 사람이 확인한다.

## 왜 손으로 봐야 하는가

- **활성 칸 가리키기:** 포커스는 늘 그리드 입력칸(textarea)에 있고, 입력칸의 `aria-activedescendant`가 활성 칸을 가리킨다. ARIA 명세는 이 속성이 가리키는 요소가 포커스 요소의 자손(또는 aria-owns로 가진 요소)이기를 바란다. 활성 칸은 입력칸의 자손이 아니므로, 스크린 리더와 브라우저마다 따라 읽는지가 다를 수 있다. 이 페이지의 가장 중요한 확인 항목이다.
- **가상 스크롤:** 화면에 그린 행만 DOM에 있다. `aria-rowcount`·`aria-rowindex`로 전체 크기와 위치를 알리지만, 둘러보기 모드(NVDA 브라우즈 모드, VoiceOver 커서)로는 그린 행까지만 갈 수 있다.
- **헤더 줄:** 고정 칸이 있으면 한 헤더 줄이 고정 쪽·스크롤 쪽 두 `role=row`로 나뉜다 (배치를 바꾸지 않으려고). 둘은 같은 `aria-rowindex`를 갖지만, 스크린 리더가 칸의 열 제목을 바르게 읽는지 본다.

## 환경

| 스크린 리더 | 브라우저 |
|---|---|
| NVDA (Windows) | Chrome, Firefox |
| VoiceOver (macOS) | Safari, Chrome |

데모: https://herbcookey.github.io/pyogrid/demo/ (`?lang=ko`). 주로 weekly(고정 칸, 다단 헤더, 행 선택, 합계 행), editors(편집기, 체크박스), summary(그룹 소계, 트리), big(5만 행)을 쓴다.

## 확인 항목

| # | 할 일 | 맞게 읽는 것 |
|---|---|---|
| 1 | Tab으로 그리드에 들어간다 | 입력칸 이름("셀 입력")과 함께 그리드·표로 알리고, 가능하면 행·열 수를 읽는다 |
| 2 | 칸을 누르거나 방향키로 옮긴다 | 옮길 때마다 새 칸의 값과 열 제목, 행·열 번호를 읽는다. 앞 칸을 다시 읽지 않는다 |
| 3 | big 데모에서 Ctrl+End(마지막 칸)로 간다 | 행 번호가 전체 기준(50,000번대)이다 |
| 4 | 고정 컬럼(weekly의 첫 두 컬럼)과 스크롤 컬럼 사이를 오간다 | 양쪽 모두 열 제목을 바르게 읽는다. 다단 헤더면 묶음 제목도 읽는지 적는다 |
| 5 | 편집할 수 있는 칸에서 글자를 친다 | 입력칸(편집)으로 바뀐 것을 알리고, 친 글자를 읽는다. Enter 뒤에는 다음 칸을 읽는다 |
| 6 | Esc로 편집을 취소한다 | 다시 칸 값을 읽는다 |
| 7 | Shift+방향키로 범위를 넓힌다 | 끝 칸을 읽는다. 아래 바의 선택 합계("6셀 선택 · ...")를 알림으로 읽는다 (aria-live) |
| 8 | 행 선택 칸·헤더의 전체 선택을 누른다 | 체크박스와 이름("(전체 선택)"), 켜짐·꺼짐을 읽는다. 행이 선택됨으로 바뀌었다고 알리는지 적는다 |
| 9 | editors 데모의 체크박스 편집기 칸에서 Space | 이름(컬럼 제목)과 바뀐 상태를 읽는다 |
| 10 | 정렬할 수 있는 헤더를 누른다 | 오름차순·내림차순 상태를 읽는다 (aria-sort) |
| 11 | 헤더의 필터 단추 | "필터" 단추로 읽는다. 팝업이 대화 상자로 열리고 검색칸·목록·단추를 읽는다 |
| 12 | summary 데모의 소계 행·합계 행으로 간다 | 소계·합계 글자를 칸으로 읽는다 |
| 13 | 트리의 펼침 단추 | 펼침·접힘 상태를 읽는다 |
| 14 | 마우스 휠로 활성 칸을 화면 밖으로 보낸 뒤 방향키 | 칸으로 돌아와(스크롤) 새 칸을 읽는다. 이상한 요소를 읽지 않는다 |
| 15 | NVDA 브라우즈 모드(Insert+Space로 바꿈)에서 표 탐색(Ctrl+Alt+방향키) | 그린 행 안에서 칸을 옮길 수 있다. 끝에서 멈추는지, 엉뚱한 곳으로 가는지 적는다 |
